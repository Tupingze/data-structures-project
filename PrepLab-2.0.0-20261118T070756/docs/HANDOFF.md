# PrepLab 移轉與接手

## 需要交接的三樣東西

1. **程式 ZIP**：原始碼、測試、啟動方式、文件與檔案雜湊。接手者可修改並重新打包。
2. **完整資料備份 JSON**：從網站設定下載。含履歷、題庫、未完成進度、歷史、GPT 回饋、重答與錄音。只交 ZIP 不會搬走瀏覽器資料。
3. **自己的服務設定**：OpenAI 金鑰另行設定。既有網站帳戶權限、網址、付費額度及金鑰不會隨 ZIP 移轉。

## 新電腦啟動

安裝 Node.js 22+，解壓 ZIP 到一般資料夾，進入含 `package.json` 的目錄。

```sh
npm run verify:handoff
npm test
npm start
```

開啟 http://127.0.0.1:4173 。Windows 也可雙擊 `start-windows.cmd`。不需要 npm install，也不依賴原作者電腦的絕對路徑。若連接埠被占用，可在 `.env` 修改 `PORT=4174`。

## 資料移轉步驟與範圍

1. 舊裝置停止錄音，等候逐字稿完成；暫停練習。
2. 設定 → 下載完整備份，確認瀏覽器實際保存 JSON 檔。檔案含個人資料，交給指定接手者。
3. 新裝置啟動程式，設定 → 還原完整備份 → 選取 JSON。
4. 確認題目、歷史與錄音數量；按「備份目前資料並還原」。會覆蓋新裝置資料並先下載復原備份；請確認下載成功。
5. 首頁按「繼續練習」，確認回答、程式與追問；到歷史回顧檢查重答與錄音。

支援文字 3 MB、錄音合計 50 MB、整個檔案 80 MB、最多 500 場歷史與 2,000 段錄音。SHA-256 偵測意外毀損，不是加密或可信簽章。無法讀取的版本或毀損內容會先拒絕。錄音保存受瀏覽器容量限制；容量錯誤會通知。

「無損」指已保存且格式支援的資料，包含文字原文、程式、metadata 與錄音二進位；不包括帳戶權限、金鑰、未完成的外部 AI 請求。舊版 v1 在記憶體中的錄音若已重新整理遺失，無法復原。v2 已保存的錄音才會移轉。舊版純文字 JSON 可匯入，但不會補出錄音。

## 金鑰稍後設定

複製 `.env.example` 成 `.env`。填入 `OPENAI_API_KEY` 後重啟。預設文字模型 `gpt-4.1`、語音 `gpt-realtime`、逐字稿 `gpt-4o-mini-transcribe`；皆可透過環境變數修改，需帳戶有相應權限。金鑰存在不表示額度或模型可用。設定後依 DEMO.md 做短文字和語音實測。

對外監聽需設定 `APP_ACCESS_TOKEN`，使用者將此存取碼填入網頁。本機預設只聽 `127.0.0.1`。正式對外服務需 HTTPS；目前沒有註冊登入、多租戶隔離或持久化全域用量管理，不宜直接當公開商用服務。

## Docker 與 Sites

Docker 配置已附，尚未執行驗證。準備 `.env` 並設定 `APP_ACCESS_TOKEN` 後可 `docker compose up --build`。容器內 HOST 為 `0.0.0.0`，即使本機映射也需要存取碼。

既有 Sites 網站保留原擁有者的私人權限；ZIP 不包含 `.openai/hosting.json` 的既有帳戶識別。接手者若用 Sites，需建立自己的專案與 hosting 設定，再 `npm run build:sites`。Worker 版本依賴 Sites 私人存取閘門；不可把此信任設定直接部署到沒有保護的平台。其他平台建議使用 Node 伺服器並設存取碼。Sites 環境變數與本機 `.env` 分開設定。

## 三人分工

| 成員 | 主要檔案 | 可驗收成果 |
|---|---|---|
| A 介面與流程 | app.js、style.css、features.js | 設定、作答、暫停、回顧、重答 |
| B AI 與語音 | server/api.mjs、ai-client.js、realtime.js | 模型契約、錯誤處理、逐字稿與追問 |
| C 資料與驗證 | portability.js、audio-store.js、tests、scripts | 備份還原、測試、打包、Demo |

題庫與難度修改題目管理或 `dist/domain.js`；不要直接改歷史場次。修改前後跑相關測試，交付前重新 `npm run handoff`。
