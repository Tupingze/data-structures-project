# PrepLab 2.0 交接單四階段驗收指南

依據《PrepLab 2.0 專案交接單》與 `PrepLab-2.0.0-20261118T070756/docs/DEMO.md`，依序執行以下四個階段。未經使用者明確同意，不可跳步或略過失敗項目。

---

## 階段 1｜設定服務
- [ ] 在 `PrepLab-2.0.0-20261118T070756/` 複製 `.env.example` 為 `.env`。
- [ ] 由使用者自行填入 `OPENAI_API_KEY`（Agent 絕不可讀取、記錄或將真實金鑰寫入追蹤檔案／對話輸出），確認文字／語音／逐字稿模型名稱與帳戶額度權限；若需對外監聽，另設 `APP_ACCESS_TOKEN`。
- [ ] 啟動 `npm start`（`http://127.0.0.1:4173`）並檢查 `GET /api/health` 回傳 `configured: true`（注意：`configured: true` 只表示金鑰存在，不代表上游連線或額度一定成功）。

## 階段 2｜實測文字面試
- [ ] 使用短背景、3 題進行真實 GPT 出題，確認題目格式與數量符合預期。
- [ ] 完整跑完：**出題 → 回答（含 C++ 編輯器作答）→ 追問 → 回饋 → 重答比較**。
- [ ] 人工核對回饋中的「引用原文（evidence）」是否逐字出自回答且技術內容合理。
- [ ] 實測錯誤邊界：**斷線、逾時、額度不足**時，確認系統會誠實顯示錯誤，**絕不偷偷降級或偽裝成假 AI 結果**。
- [ ] 記錄實測的回應延遲與實際費用。

## 階段 3｜實測語音
- [ ] 使用真實麥克風連線語音模式，驗證瀏覽器收音與面試官播音正常。
- [ ] 確認主回答結束後產生逐字稿與**每題唯一一次**追問。
- [ ] 回答追問後**等候逐字稿與儲存完成再換題**，重新整理頁面確認歷史錄音可正常播放。
- [ ] 實測錯誤邊界：**拒絕麥克風權限、網路斷線與重連**，確認狀態恢復正常、不殘留卡死狀態。
- [ ] 記錄語音延遲與逐字稿誤字情況（錄音前須取得參與者同意）。

## 階段 4｜調整並完成 Demo 與重新打包
- [ ] 依教授要求調整職務題目、難度與回饋標準（改題庫管理或 `dist/domain.js`，**不得改動歷史場次**）。
- [ ] 依 `docs/DEMO.md` 以無金鑰示範模式與真實帳戶各完整演練一次 Demo。
- [ ] 整理系統限制與三位組員（A 介面與流程 / B AI 與語音 / C 資料與驗證）實際貢獻。
- [ ] 交付打包前執行：
  1. `npm test`（確認所有離線測試全數通過）
  2. `npm run handoff`（於 `releases/` 產出新版獨立開發 ZIP 與 `HANDOFF-MANIFEST.json`）
  3. 解壓新產出的 ZIP 或對產出目錄執行 `npm run verify:handoff` 確認檔案雜湊全數通過。

---

## 每階段收尾動作（強制）
每完成任一階段的驗收或修正，立即依 `update-agents-md` skill 同步更新 `PrepLab-2.0.0-20261118T070756/AGENTS.md` 的 `## 1. Living Status`（更新日期、勾選 `[x]`、記錄實測延遲／費用／問題與近期變更）。
